# Hello Kivy — Kivy UI smoke test for kivy-ios 3.0

Minimal Kivy app (`Label` with "Hello Kivy") using the official **python.org**
iOS `Python.xcframework` preview (**3.15.0b2**).

Kivy **3.0** iOS wheels are not on PyPI yet for cp315. This example uses
**Path A**: build wheels locally into the shared [`examples/wheels/`](../wheels/)
directory and let `toolchain lock` pin them by repo-relative `path`.

## Prerequisites

- macOS with Xcode (same as [hello-world](../hello-world/README.md))
- Metal Toolchain installed (`xcodebuild -downloadComponent MetalToolchain` if
  `xcrun -find metal` fails — required for Kivy's SDL3 iOS deps)
- **CPython 3.15 macOS framework** from [python.org](https://www.python.org/ftp/python/3.15.0/python-3.15.0b2-macos11.pkg)
  (`sudo installer -pkg … -target /`) — cibuildwheel needs this host Python to
  cross-build `cp315` iOS wheels
- kivy-ios 3.0 installed from this repo (`pip install -e ".[dev]"`)

## 1. Build iOS wheels locally

From the repo root (one-time; 30–60 minutes depending on cache):

```bash
chmod +x scripts/build_ios_wheels.sh
scripts/build_ios_wheels.sh
```

This clones [kivy/kivy](https://github.com/kivy/kivy), cross-builds SDL3/ANGLE
deps, runs `cibuildwheel` 4.0+ with `CIBW_ENABLE=cpython-prerelease` for
`cp315` on all three iOS slices, and copies the resulting wheels into
`examples/wheels/` (shared by all Kivy examples).

Re-run after updating Kivy or Python preview versions.

Wheels are built with `IPHONEOS_DEPLOYMENT_TARGET=16.0` (Kivy's SDL3/ANGLE
xcframeworks require iOS 16+). Filenames use PEP 730 tags such as
`ios_16_0_arm64_iphonesimulator`. Override with `IOS_DEPLOYMENT_TARGET=…` when
running the script; if you change it, also update `deployment_target` in
`pyproject.toml` to match.

After rebuilding, remove any old `ios_13_0_*` wheels from `examples/wheels/`
before re-locking.

If `toolchain lock` fails because wheels are missing, run `toolchain doctor` —
it checks that each `[tool.kivy.ios].find_links` directory exists and contains
`.whl` files before you hit a cryptic pip error.

## 2. Lock, build, run

```bash
cd examples/hello-kivy
toolchain lock --update
toolchain build --simulator
toolchain run --simulator
```

`[tool.kivy.ios].find_links = ["../wheels"]` tells `toolchain lock` to resolve
Kivy from the shared vendored directory; pure-Python deps (e.g.
`more-itertools`) still come from PyPI. The lockfile records `path` + SHA-256 for
each local wheel slice.

## Files

| Path | Purpose |
|------|---------|
| `pyproject.toml` | App config + `find_links` for shared vendored wheels |
| `../wheels/` | Locally built Kivy iOS wheels (gitignored `.whl` blobs) |
| `pylock.ios.toml` | Generated by `toolchain lock` |
| `src/main.py` | Kivy `App` with a single `Label` |
